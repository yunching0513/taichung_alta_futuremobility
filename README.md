# 臺中：都市空間與未來移動

臺中市的住宅、移動、人口與土地使用，收成一份指得出出處的資料集。
空間單位是29個行政區，不是縣市。

## 為什麼另開一個 repo

[`yunching0513/housing`](https://github.com/yunching0513/housing) 處理的是全國22縣市的住宅供需，
臺中在那裡只是22分之一。唯臺中的問題不完全是住宅問題：
**它是六都之中所得成長最快、自有率卻最低的城市，同時空屋率六都最高。**
這三件事同時成立，靠住宅一個切面解釋不了。

移動那一面同樣如此。臺中全市的日夜間人口比0.997，日間3,043,848人、夜間3,052,296人，
看起來是一個通勤圈與市界幾乎重合、自給自足的城市。
唯拆到區級，從外埔區的0.819到西屯區的1.198，全距0.379。
**全市那個接近1的漂亮數字，是兩組方向相反的失衡互相抵銷出來的。**
本 repo 因此獨立出來：範圍比住宅寬，尺度比全國細。

分工是這樣：全國層級的住宅比較留在 `housing`，臺中的區級與跨部門資料放這裡。
兩邊重疊的數字（例如社宅戶數、租金中位數）以 `housing` 的解析結果為準，本 repo 不另算一份。

## 兩張圖疊起來看：29個區的空屋與通勤

普查空屋率（民國109年）與日夜間人口比（電信信令，民國112年11月），兩者的區級極端值：

| 區 | 空屋率 | 日夜比 | 住宅 | 家戶 |
|---|---|---|---|---|
| 西屯區 | 19.05% | 1.198 | 114,057 | 98,068 |
| 中區 | 28.57% | 1.168 | 9,415 | 10,399 |
| 西區 | 15.64% | 1.164 | 57,573 | 45,148 |
| 清水區 | 19.68% | 0.864 | 31,410 | 26,973 |
| 北屯區 | 11.76% | 0.852 | 117,511 | 101,548 |
| 外埔區 | 9.51% | 0.819 | 9,304 | 9,483 |

空屋率最高的中區28.57%與最低的龍井區7.15%相差21.4個百分點，
而臺中市與臺北市之間的市際落差只有3.90個百分點；**區內落差是市際落差的五倍以上。**

直覺上會猜「白天聚集人的地方，就是晚上空著的地方」，唯資料不支持這個猜測：
29個區的空屋率與日夜比的相關係數只有0.282，是弱相關。
西屯區與中區確實同時具備高日夜比與高空屋率，
可是清水區的空屋率19.68%配上0.864的日夜比，方向剛好相反。
**這代表臺中的空屋至少有兩種成因，用同一套解釋會失真**，
而區分它們需要更細的資料：屋齡、建物型態、產權年份、以及通勤的起訖對。
這是本 repo 想回答的第一個問題。

還有一個現象值得追：中區的住宅9,415宅少於家戶10,399戶，
烏日區、龍井區、大肚區、外埔區也是同樣的方向。
住宅比家戶少、空屋率卻不低，這兩件事要並存，只可能是存量的位置與需求的位置對不上。

成追線虛線，高鐵另一色。臺中境內共23個臺鐵車站，依本研究從線形算出的三級標示：
與高鐵線相距400公尺內的轉乘站（新烏日）、山海線的交會站（追分、成功）、一般站。
**這個分別不是臺鐵官方的站等**，官方站等分特等至招呼共六級，來源檔沒有那個欄位。
臺中捷運綠線也不在來源檔裡，兩者都列在待收清單。

大型地圖可以縮放到8倍：右上角的 `+` `−` `RESET`、雙擊、雙指、方向鍵都可以，
⌘／Ctrl 加滾輪也可以（單獨滾輪維持捲頁面，否則滑鼠每次經過都會把捲動吃掉，
右上角的「滾輪」開關可以改掉這個行為）。放大時線寬固定、文字反向縮小，
兩者都是為了讓放大真的等於看得更清楚：**放到8倍時，一條跟著放大的區界會粗到蓋掉
它本來要分隔的填色**。中區只有0.9平方公里，全圖時塞不下標籤，放大過2.2倍才顯示。

視覺沿用 VZT 風格指南：單一強調色（石灰黃綠 #C8D400）、大量留白、
超細字重配超大字號、中英並陳。刻意只做淺色一套，深色版會把「留白為主體」這件事推翻。
唯一的外部請求是 Google Fonts，字型連不到時有系統字型後備，版面仍然成立。

## 資料夾結構

```
data_TW/    原始檔。政府網站下載的原樣，不修改
data/       解析後的中間檔（JSON），版面唯一的資料來源
scripts/    解析程式，一支對一份中間檔
src/        版面模板
docs/       資料來源清單與方法筆記
```

方向是單向的：`data_TW/` → `scripts/` → `data/` → `src/`。
版面不直接讀原始檔，解析程式不回頭改版面。

## 三條規矩

1. **數字要有出處。** 版面上的統計數字一律從 `data/*.json` 讀，不硬編進模板。
   來源更新的那一天，手寫的數字會靜靜地變成錯的，而且沒有人會發現。
2. **算不出來就給 `null`。** 樣本不足、定義斷掉、期別對不上的時候，寧可留白並標明原因，
   也不要給一個看起來像數字的東西。
3. **定義變過的地方要標出來。** 例如主計總處在民國112年把「建坪」改成不含陽台與露臺，
   臺中的每戶建坪中位數因此從111年的45坪掉到112年的42坪；那不是房子變小。
   跨過這種斷點畫出來的線會很好看，也會是錯的。

期別也一樣要標。上面那張表裡，空屋率是民國109年、信令是112年11月、
社宅進度是115年7月，三個不同的時間點；同一格內的比較成立，跨格比較要先看期別。

## 里級人口那一節為什麼有七個區是粗的

第04節把尺度從29個區縮到625個里。密度最高的東區富台里是42,840人每平方公里，
最低的和平區平等里是3人，**相差一萬四千倍**；區級的全距做不到這個量級，
一個區的平均把里與里之間的差異抹平了。色階因此取對數，線性色階之下除了舊市區以外全部是白的。

唯有七個區只畫得到區級，原因不是缺資料，是**缺界線**。
人口來自內政部戶政司民國114年的逐村里統計，那一份是完整的；
界線目前只拿得到 g0v 的民國71年版，625個里對上593個多邊形。
被再分割的里，同名的舊多邊形範圍比現在**大**，把現在的人口填進去，
畫出來的密度會偏低而且偏得沒有規律。**那不是缺一塊，那是畫錯。**
因此規則寫成：一個區的每一個里都對得到多邊形才畫到里，只要有一個對不到就整個區退回區級，
並在圖上加斜線網底。目前22個區畫到里（457個里、
70.0%的人口），7個區畫到區級，
太平區最嚴重：39個里只有19個多邊形。

要升級這七個區，需要內政部的現行村里界圖（政府資料開放平臺 dataset 7438，民國115年6月24日版）。
那份檔案放在 tgos.tw，本專案目前的網路環境取不到，回403。
拿得到的話換掉 `data_TW/from_moi/village_geo_taichung.json` 再重跑 `prep_villages.py` 即可，
程式不必改。

## 公車與車禍這兩節在說什麼

**第06節：線寬與濃度都是班次。** 一張每條線一樣粗的公車路線圖，讀到的是「有沒有公車」，
那個命題在臺中29個區裡幾乎處處成立，等於沒有資訊。
**可及性的變數從來不是有沒有車，而是多久來一班。**
680條子路線的班表給逐班的發車時刻，直接數；
只有16條給班距，才用時段長度除以班距去估，兩者分開標記。
共用走廊會因為多條線疊在一起而變深，那是視覺的疊加，不是加總出來的數字：
TDX 的線形逐路線各自一條折線，走同一段臺灣大道的十幾條線頂點對不齊，加不起來。

**第07節：十年1,607人。** 平均每年160.7人，
其中64%的受害者是機車騎士、
18%是行人。
**中區是唯一一個行人多過機車的區**，十年22人裡行人占68%，全市的比例剛好相反。

**一個被擋下來的假發現。** 把第06節的公車服務與第07節的死亡率放在一起，
每千人班次與每十萬人死亡的相關係數是 **+0.617**，看起來像「公車越多的地方死越多人」。
唯兩邊共用同一個人口分母，人口少的區在兩邊同時偏高，係數是被分母自己撐起來的。
把公車那一邊的分母換成面積，同一組區的係數掉到 **+0.037**：那個關係本來就不存在。
站得住的是另一個方向，人口密度與每十萬人死亡的係數是 **−0.347**，
越稀疏的區每十萬人死亡越高。三個係數頁面上都寫出來，不只留最好看的那一個。

## TDX 金鑰放哪裡

臺中捷運綠線、高鐵臺中站座標、臺鐵官方站等、公車的路線線形與班表，這幾項都在交通部TDX，
而TDX需要金鑰。原始檔已經抓下來並納入版控，**只有要更新資料時才需要金鑰**。到 <https://tdx.transportdata.tw> 註冊會員，於「資料服務」頁申請，
會拿到一組 `client_id` 與 `client_secret`。三個地方可以放，擇一：

**其一，GitHub 的 repository secrets（建議）。**
到 Settings → Secrets and variables → Actions → New repository secret，
分別建 `TDX_CLIENT_ID` 與 `TDX_CLIENT_SECRET`。
之後在 Actions 頁手動跑「抓 TDX 資料」這個工作流程，它會抓完、重跑管線、直接提交。
金鑰只存在GitHub的加密儲存區，不經過任何對話、不落在筆電上、不進版控，
而且GitHub會把它在log裡遮成 `***`。

**其二，本機的 `.env`。** 把 `.env.example` 複製成 `.env` 填上兩行，再跑：

```
python3 scripts/fetch_tdx.py
python3 scripts/prep_rail.py
```

`.env` 已列入 `.gitignore`。刻意不接受命令列參數傳金鑰：那會留在 shell 的歷史紀錄裡。

**其三，環境變數。** `export TDX_CLIENT_ID=... ; export TDX_CLIENT_SECRET=...` 之後同上。

三種都不會讓金鑰進到這個公開的 repo。**平常的部署不需要金鑰**：
`pages.yml` 只讀已經納入版控的原始檔，抓資料與建置是兩支分開的工作流程。
